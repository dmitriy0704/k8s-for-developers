DestinationRule — это специальный ресурс (CRD) в Kubernetes, который используется в платформе Istio Service Mesh для настройки поведения сетевого трафика после того, как маршрутизация уже произошла.
Если VirtualService решает, куда именно направить запрос (например, на какой сервис), то DestinationRule определяет, как этот трафик должен обрабатываться при достижении конечной цели.

Основные функции DestinationRule

- Подмножества (Subsets): Позволяют разделить версии одного сервиса (например, v1, v2, canary) на основе меток (labels) подов, чтобы перенаправлять на них трафик из VirtualService.
- Балансировка нагрузки (Load Balancing): Настройка алгоритмов распределения запросов (например, случайный выбор, взвешенный ROUND_ROBIN, наименьшее количество соединений LEAST_REQUEST или хеширование).
- Пул соединений (Connection Pools): Ограничение максимального числа HTTP- или TCP-соединений и таймаутов.
- Предохранители / Изоляция сбоев (Outlier Detection): Автоматическое исключение «больных» подов из пула балансировки при появлении ошибок (например, серии 5xx).
- Настройка TLS: Задание параметров шифрования и взаимной аутентификации (mTLS) для связи с сервисом.

Пример конфигурации

Пример описывает создание подмножеств v1 и v2 для сервиса my-service и включение простого алгоритма балансировки:

```yaml
apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: my-service-rule
  namespace: default
spec:
  host: my-service
  trafficPolicy:
    loadBalancer:
      simple: ROUND_ROBIN
  subsets:
  - name: v1
    labels:
      version: v1
  - name: v2
    labels:
      version: v2

```
