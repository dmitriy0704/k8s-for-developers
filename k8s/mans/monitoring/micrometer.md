# Micrometer

В контексте Java-разработки Micrometer — это инструмент для сбора и отправки метрик из вашего приложения в системы мониторинга. [1] (https://habr.com/ru/companies/otus/articles/650871/)
Его часто называют «SLF4J, но для метрик». Как SLF4J предоставляет единый интерфейс для разных библиотек логирования (Logback, Log4j2), так и Micrometer предоставляет единый фасад (интерфейс) для сбора телеметрии. Вы пишете код один раз, а отправлять метрики можете куда угодно: в Prometheus, Datadog, New Relic, InfluxDB или Graphite. [1] (https://dou.ua/forums/topic/35745/), [2] (https://habr.com/ru/companies/otus/articles/650871/)
Поскольку мы только что обсуждали Resilience4j, связь прямая: Micrometer автоматически собирает данные о работе ваших Circuit Breaker'ов, TimeLimiter'ов и Retry, чтобы вы могли построить по ним графики в Grafana.

🛠 Что конкретно умеет делать Micrometer?

1. Измерять всё подряд внутри кода. Он предоставляет встроенные примитивы (типы счетчиков):
	• Counter (Счетчик): Измеряет только то, что растет (количество запросов, число ошибок, количество успешно обработанных заказов).
	• Gauge (Калибр): Показывает текущее значение в данный момент времени (загрузка процессора, количество активных потоков в Thread Pool, размер очереди). Значение может как расти, так и падать.
	• Timer (Таймер): Измеряет задержки (сколько миллисекунд выполнялся SQL-запрос или как долго отвечал внешний API). Кроме времени, он также считает количество событий.
	• Distribution Summary: Используется для анализа распределения величин (например, объем скачиваемых файлов в байтах).
2. Собирать системные метрики (из коробки). Если вы используете Spring Boot Actuator, Micrometer автоматически соберет данные о JVM (использование памяти Garbage Collector'ом, потоки), потреблении CPU, HTTP-запросах к вашим контроллерам и пулах соединений с базой данных (HikariCP).
3. Обогащать данные тегами (Tags / Dimensions). Вы можете не просто отправлять метрику http_requests_total, а прикреплять к ней теги: method="GET", status="200", uri="/api/users". Это позволяет гибко фильтровать и группировать графики.

🔗 Как это работает в связке с Resilience4j?

Resilience4j имеет встроенный модуль интеграции с Micrometer (resilience4j-micrometer). Благодаря этому вы получаете наглядные метрики для каждого паттерна. Например:
• Для Circuit Breaker: в каком состоянии он находится (open/closed), сколько медленных вызовов зафиксировано, сколько запросов сброшено.
• Для TimeLimiter: сколько запросов завершилось по таймауту.
• Для Rate Limiter: сколько запросов было заблокировано из-за превышения лимитов.
Micrometer упаковывает эти данные, а условный Prometheus забирает их раз в несколько секунд. В итоге на дашборде в Grafana вы сразу видите красивый график: «В 14:00 внешний сервис начал тормозить, сработал TimeLimiter, а следом Circuit Breaker ушел в OPEN».
