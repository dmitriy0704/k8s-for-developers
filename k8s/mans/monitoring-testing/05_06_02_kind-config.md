# Комментарии к файлу конфигурации kind

> я создал kind кластер, с таким конфигом

```yaml
kind: Cluster
 apiVersion: kind.x-k8s.io/v1alpha4
 nodes:
 - role: control-plane
 extraPortMappings:
 - containerPort: 80
 hostPort: 80
 - containerPort: 443
 hostPort: 443
```
> помоги в нем разобраться

Этот конфиг создает одноузловой кластер Kubernetes, где стандартные веб-порты вашего Mac (80 и 443) напрямую соединены с портами внутри кластера. Это позволяет принимать HTTP и HTTPS запросы (например, от k6 или браузера) по простому адресу http://localhost без указания номера порта.

Разбор каждой строки конфига

- kind: Cluster и apiVersion: kind.x-k8s.io/v1alpha4 — служебные заголовки, которые говорят утилите kind, что этот файл описывает конфигурацию нового кластера.
- nodes: — список виртуальных узлов (нод), из которых будет состоять кластер.
- - role: control-plane — создает один главный узел. В Kind он выполняет сразу две роли: управляет всем кластером и запускает ваши поды с микросервисами.
- extraPortMappings: — настройка проброса сетевых портов между вашим Mac (хостом) и Docker-контейнером ноды Kind.
	- hostPort: 80 -> containerPort: 80 — весь обычный веб-трафик (HTTP), который приходит на localhost:80 вашего Mac, перенаправляется на порт 80 внутри ноды Kind.
	- hostPort: 443 -> containerPort: 443 — то же самое для защищенного трафика (HTTPS) на порту 443.

Важный нюанс для вашего стека (Spring Cloud Gateway / Istio)

В Kubernetes обычные сервисы типа NodePort по умолчанию могут занимать только порты в диапазоне 30000–32767. Порты 80 и 443 являются системными (ниже 1024), поэтому обычный Service с типом NodePort не сможет занять порт 80 внутри кластера.
Чтобы трафик с hostPort: 80 дошел до вашего приложения, у вас есть два рабочих пути:
1. Использовать Istio Ingress Gateway или Nginx Ingress. Если вы поставите Istio с профилем default (или установите Ingress-контроллер с поддержкой hostNetwork: true), он сможет привязаться напрямую к порту 80 ноды и перенаправлять запросы в ваш Spring Cloud Gateway.
2. Использовать hostPort в поде Spring Cloud Gateway. Если вы не ставите Istio Ingress Gateway, в манифесте Deployment вашего Spring Cloud Gateway в секции ports нужно добавить hostPort: 80 (тогда под шлюза напрямую «сядет» на 80-й порт ноды и примет трафик с Mac).

Как проверить, что проброс портов работает

Выполните в терминале Mac команду docker ps. В колонке PORTS у вашего контейнера ...-control-plane вы должны увидеть запись вида:
0.0.0.0:80->80/tcp, 0.0.0.0:443->443/tcp
Это подтверждает, что Docker Desktop успешно открыл порты 80 и 443 на вашем Mac и направил их в кластер.
Каким способом вы планируете принимать внешний трафик от k6 — через Istio Ingress Gateway или напрямую в ваш Spring Cloud Gateway? Подскажу точный YAML-манифест под выбранный вариант.
